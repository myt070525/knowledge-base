## 1. 这个项目到底是什么

**论文标题**：MCEval-AgriQA: Evaluating Multi-Faceted Capabilities of Large Language Models on the Chinese Agricultural-Aware Question Answering Dataset: A Preliminary Study

**作者单位**：西南大学计算机与信息科学学院；贵州省大数据重点实验室 / 贵州大学计算机科学与信息学院；重庆大学大数据与软件学院。通讯作者 Sheng Yongpan。

**一句话概括**：面向中文农业问答，构建了一个 **3,470 条的五类任务数据集**，并配套一套 **自动化多维能力评测框架**，用来横向比较通用大模型、农业领域模型和 LoRA 微调模型在农业场景下的能力差异，同时系统研究 5 种提示策略与任务类型之间的交互影响。

**框架四阶段**：

1. 中文农业问答数据集构建（采集 → 预处理 → 任务划分与映射 → 解释与场景增强）
2. 提示策略设计与模板生成（Zero-shot / Few-shot / Few-shot Role / CoT / Few-shot-CoT）
3. 模型选择与微调（通用开源模型 + 农业领域模型 + QLoRA 微调）
4. 能力评测与分析（分题型指标 + LLM Judge + 模型级/提示级对比）

## 3. 代码框架

**入口关系**（来自代码包 README）：

```
完整 689 题的单个 Qwen2.5 实验
└─ tools/run_full_prompt.py
   └─ runners/run_experiment.py

按任务运行论文中的十组实验
├─ tools/run_closed_set_seed8888.py
├─ tools/run_completion_seed8888.py
├─ tools/run_open_generation_seed8888.py
└─ tools/run_reasoning_seed8888.py
   ├─ Ollama 模型   → runners/run_experiment.py
   └─ ChatGLM2 / PLLaMA / Agri-LoRA → runners/run_local_any_dataset.py
```

| 模块 | 职责 |
| --- | --- |
| `tools/` | 编排层。7 个脚本，`run_full_prompt.py` 跑单模型单提示策略的 689 题全量实验，4 个 `*_seed8888.py` 跑分任务的十组实验 |
| `runners/` | 执行层。`run_experiment.py`（Ollama/API）、`run_local_any_dataset.py`（本地 HF 模型）、`run_local_model.py` |
| `prompts/` | `prompt_builder.py` 模板渲染、`fewshot_sampler.py` 示例抽样（**few-shot 示例只取自 dev 集，避免数据泄漏**） |
| `evaluation/` | `metrics.py`（`evaluate_predictions` 为主入口，约 530 行）、`llm_judge.py`（DeepSeek-Flash 打分）、`postprocess_answers.py`、`evaluate_predictions.py` |
| `configs/` | 10 个模型 YAML（qwen2.5-7b / qwen3-8b / deepseek-r1-distill-7b / chatglm2-6b / pllama-13b / agri-lora 等）+ 5 个提示 YAML |
| `utils/` | `task_mapping.py`（任务分组归一化）、`model_loader.py`、`io_utils.py`、`logging_utils.py` |

**关键硬约束**（`tools/run_full_prompt.py` 中的断言，改动时必须遵守）：

- 输入必须是**有序**的 `agrieval_test_000001..000689`，且**字段顺序**必须严格等于九字段 schema
- 689 题按 `task_type` 拆成 **669 标准题（max_tokens=500）+ 20 推理题（max_tokens=1000）**
- 统一实验参数：**seed=8888、temperature=0.15**；`--seed` 与 `--model-seed` 不一致时程序直接报错
- YAML 中的默认 seed 会被命令行覆盖，不会静默混用

**模型配置示例**：

```yaml
model_id: qwen2_5_7b_instruct_ollama
display_name: Qwen2.5-7B-Instruct (Ollama qwen2.5:7b)
provider: ollama
model: qwen2.5:7b
base_url: http://127.0.0.1:11434
temperature: 0.15
max_tokens: 500
seed: 42
timeout: 300
keep_alive: 5m
```

## 4. 评测指标（按题型定制）

| 题型 | 指标 | 说明 |
| --- | --- | --- |
| 判断题、单选题 | **Accuracy**、**Macro-F1** | 单标签，闭集 |
| 多选题 | **EM**（选项集合完全一致）、**Micro-F1**（部分匹配） | 多标签 |
| 填空题 | **EM**（先做 normalize：去空格标点）、**Token-F1** | 字/词级重叠 |
| 简答题、术语解释题、情景推理题 | **LLM Judge 1–5 分** | 由 DeepSeek-Flash 按农业评分细则打分 |

LLM Judge 评分细则维度：事实正确性、完整性、相关性、专业表达、推理质量、实用建议。

## 5. 论文基线结果（我们的复现靶子）

**Table 4 — Few-shot-CoT 提示下各模型在 test 集的表现**

| 模型 | 闭集 Acc | 闭集 Macro-F1 | 多标签 EM | 多标签 Micro-F1 | 补全 EM | 补全 Token-F1 | 开放生成 LLM Score | 推理 LLM Score |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Qwen2.5-7B-Instruct | 65.9 | 75.2 | 37.5 | 80.0 | 12.9 | 45.8 | 3.32 | 4.36 |
| DeepSeek-R1-7B | 47.5 | 49.1 | 16.7 | 58.2 | 3.6 | 21.1 | 2.33 | 2.90 |
| Qwen3-8B | 65.9 | 65.8 | 41.7 | 74.6 | 12.9 | 40.1 | 3.36 | 4.50 |
| ChatGLM2-6B | 44.7 | 45.1 | 12.5 | 71.6 | 0.7 | 11.3 | 1.81 | 2.40 |
| PLLaMa-13B-Instruct | 40.2 | 38.5 | 8.3 | 63.8 | 1.4 | 3.4 | 2.16 | 2.50 |
| **Qwen2.5-7B + Agri-LoRA** | **67.0** | **75.5** | **45.8** | **81.6** | **15.8** | **50.4** | 3.64 | **4.60** |

**Table 5 — Qwen2.5-7B-Instruct 在 5 种提示策略下的表现**

| 提示策略 | 闭集 Acc | 闭集 Macro-F1 | 多标签 EM | 多标签 Micro-F1 | 补全 EM | 补全 Token-F1 | 开放生成 LLM Score | 推理 LLM Score |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Zero-shot | 65.4 | 63.4 | 37.5 | **86.7** | 9.4 | 42.7 | 2.96 | 4.15 |
| Few-shot | 62.6 | 60.6 | 45.8 | 80.0 | 12.2 | 45.5 | 3.18 | 3.90 |
| Few-shot Role | 62.6 | 60.2 | **58.3** | 89.6 | 10.8 | 43.5 | 3.25 | 4.05 |
| CoT | 62.6 | 70.2 | 41.7 | 84.7 | 11.5 | 44.7 | 3.12 | 4.28 |
| **Few-shot-CoT** | **65.9** | **75.2** | 37.5 | 80.0 | **12.9** | **45.8** | **3.32** | **4.36** |

**论文核心结论**：

1. 通用开源模型已具备扎实的农业问答基础能力，Qwen 系列最稳；
2. 农业领域预训练（PLLaMA）**未达预期** —— 其语料以英文植物学文献为主，基座 LLaMA-2 中文能力弱；
3. **基于强通用模型做 LoRA 微调，比直接用领域预训练模型更可靠**，Agri-LoRA 在多数任务上取得最优；
4. 提示策略效果**因任务而异**：闭集任务 Zero-shot 就够好，多标签任务 Few-shot Role 最强，推理任务 CoT 有效，Few-shot + CoT 组合互补性最好。

## 6. 本机可行性评估（重要）

实测本机环境：

| 项 | 实测结果 |
| --- | --- |
| GPU | **无 NVIDIA GPU**（NVIDIA 驱动未安装） |
| CPU | Intel Core Ultra 9 285H，16 核 |
| 内存 | 31.5 GB |
| 推理框架 | Ollama **未安装**、Docker 未安装、conda 未安装 |
| Python | 系统 3.11.15；DSH 内置 3.12（含 PyMuPDF、pandas、numpy） |

**结论：论文的完整实验在本机无法直接复现。**

- Qwen2.5-7B / Qwen3-8B / DeepSeek-R1-7B 量化后约需 5–6 GB 显存，纯 CPU 推理即使可行也极慢（689 题 × 多组实验不现实）；
- PLLaMA-13B 显存需求更高，纯 CPU 基本不可行；
- QLoRA 微调在无 GPU 环境下**不可行**。

**三条可选路线**：

| 路线 | 可行性 | 说明 |
| --- | --- | --- |
| A. 实验室 GPU 服务器 / 云 GPU | 最贴合论文 | 能完整复现 Table 4、Table 5，包括 LoRA 微调 |
| B. 模型 API（DeepSeek 等） | 立即可用 | 跑通全流程与 LLM Judge；但"模型级对比"变成了 API 模型的对比，与论文不完全等价 |
| C. 本机 CPU + Ollama 小模型 | 可行但慢 | 如 Qwen2.5-1.5B/3B、Qwen3-4B，适合**验证流水线正确性**，不适合产出论文级结果 |

## 7. 建议方案（分阶段，先做不依赖 GPU 的部分）

### 阶段一：离线框架补齐（本机即可完成，无需 GPU）

1. **补齐任务子集生成器** —— 从 `test.jsonl` 按 `question_type` 切出 closed_set / multi_label / completion / open_generation / reasoning 五个有序子集，修复 README 中编排器缺少输入文件的缺口；
2. **指标模块自测** —— 用构造的"完美预测""空预测""部分匹配"案例验证 `metrics.evaluate_predictions`，确认各题型指标计算正确；
3. **流水线 dry-run** —— 用 mock 模型（直接回显 gold answer）跑通 `run_full_prompt.py` → `evaluate_predictions` 全链路，验证 schema/顺序/合并/指标落盘是否正确；
4. **提示模板渲染检查** —— 校验 5 个 prompt YAML 在 7 种题型上的渲染结果，确认 few-shot 示例只来自 dev 集。

> 产出：一套可信、可复现的评测骨架。这是后续任何模型对比的前提。

### 阶段二：模型接入（需确定路线 A / B / C）

1. 接入目标模型，跑单任务小样本（如 reasoning 20 题）验证端到端；
2. 全量 689 题 × 5 提示策略；
3. 与论文 Table 5 逐格对比，定位差异来源。

### 阶段三：向"知识库"方向扩展（待确认比赛要求）

论文的 future work 明确提到向多模态扩展。而本项目目录名为"知识库"，若比赛真正要求的是**构建农业知识库问答系统**，则自然的结合点是：

> 以 MCEval-AgriQA 作为**评测基准**，在其之上构建 RAG 式农业知识库问答系统，用论文的指标体系和 LLM Judge 量化检索增强带来的增益。

这条路线的优势：既有现成的权威评测基准，又有明确的创新增量（RAG vs 纯提示/微调）。
