# MCEval-AgriQA 上手指南

> 写给第一次接触这个项目的你。读完这一篇，你会知道：这个项目在做什么、数据长什么样、
> 一次评测是怎么跑完的、指标怎么算、代码该改哪里、以及**怎么用你自己的电脑跑起来**。
>
> 文中所有数字和模型输出都是**本机实测**，不是抄论文的。

---

## 0. 一句话讲清楚

> 老师做了一套**农业知识的考试卷**（3,470 道题，分五大类），
> 又写了一个**自动阅卷系统**，用来考各种大模型的农业水平，
> 顺便研究"换个提问方式，成绩会怎么变"。

论文标题里 `Multi-Faceted`（多面）指的是：这套卷子不只考"记不记得住"，还考**理解**、**推理**、**表达**。

## 1. 全局图：四个阶段

```
① 造数据集              ② 设计提示策略           ③ 选模型 / 微调          ④ 评测与分析
3750→3470 条             5 种问法                6 个模型                分题型算分
├ 采集（题库/教材）      ├ Zero-shot             ├ Qwen2.5-7B-Instruct   ├ 判断题/单选 → Acc, Macro-F1
├ 清洗（去重/过滤）      ├ Few-shot              ├ Qwen3-8B              ├ 多选题     → EM, Micro-F1
├ 划分 5 类任务          ├ Few-shot Role         ├ DeepSeek-R1-7B        ├ 填空题     → EM, Token-F1
└ 场景增强               ├ CoT                   ├ ChatGLM2-6B           └ 简答/术语/推理 → LLM 打分 1~5
                         └ Few-shot-CoT          ├ PLLaMa-13B
                                                 └ + Agri-LoRA（微调）
```

**你要记住的核心关系**：*同一个模型 × 不同问法 × 不同题型 → 分数不一样*。
论文最有价值的结论就是这个"不一样"的规律。

## 2. 数据长什么样

数据集在 `老师给的资料/MCEval_AgriQA代码/dataset/`，三个文件都是 JSONL（一行一题）：

| 文件 | 题量 | 用途 |
| --- | ---: | --- |
| `train.jsonl` | 2,438 | 只用于 LoRA 微调 |
| `dev.jsonl` | 343 | **只用于 few-shot 抽例子**（防数据泄漏） |
| `test.jsonl` | 689 | 最终考试卷 |

**每题 9 个字段，顺序固定**（老师代码会校验）：

```json
{"id": "agrieval_test_000001", "split": "test",
 "question": "禾谷类作物一般都具有分蘖特性",
 "question_type": "judgment", "task_type": "classification",
 "options": {}, "answer": "错误", "explanation": "", "source": "website_source"}
```

**7 种题型 → 5 大任务组**（`utils/task_mapping.py` 的映射规则）：

| 任务组 | 题型 | test 题量 |
| --- | --- | ---: |
| closed_set | 判断题 35 + 单选题 144 | 179 |
| multi_label | 多选题 24 | 24 |
| completion | 填空题 139 | 139 |
| open_generation | 术语解释 130 + 简答 197 | 327 |
| reasoning | 情景推理 20 | 20 |
| | **合计** | **689** |

> ⚠️ 老师代码包里**没有**这些子集文件，但 README 里的编排器又要求传入它们。
> 我已经写好 [make_subsets.py](../scripts/make_subsets.py) 重建，并自动校验是否与论文 Table 1 一致。

## 3. 一次评测是怎么跑完的

完整链路（**已在你机器上跑通**）：

```
dataset/test.jsonl
      │
      │  normalize_row()   ← utils/task_mapping.py 补上 task_group、gold_answer
      ▼
┌─────────────────────────────────────────────────┐
│  runners/run_experiment.py                      │
│   for 每一题:                                    │
│     build_prompt()   ← prompts/prompt_builder.py│  拼提示词（含 few-shot 例子）
│     client.generate() ← utils/model_loader.py   │  调用模型
│     postprocess_answer() ← evaluation/          │  从输出里抠出答案
│     写一行到 predictions.jsonl                   │
└─────────────────────────────────────────────────┘
      │
      ▼
evaluation/metrics.py :: evaluate_predictions()
      │
      ▼
metrics.json  +  predictions.jsonl
```

**真实执行过的命令**（5 题冒烟测试，28 秒跑完）：

```powershell
# 1. 启动本地模型（注意：必须关思考模式，见第 6 节）
cd C:\Users\ABC\llama-cpp
$env:LLAMA_ARG_CHAT_TEMPLATE_KWARGS = '{"enable_thinking": false}'
.\llama-server.exe -m models\Qwen3-8B-Q4_K_M.gguf -ngl 99 --host 127.0.0.1 --port 8080 `
    -c 32768 -np 1 -b 2048 -ub 256 --alias qwen3-8b --api-key sk-local-qwen3

# 2. 生成任务子集
$env:PYTHONIOENCODING = "utf-8"
& $PY scripts\make_subsets.py --make-demo

# 3. 跑评测
$env:LLAMACPP_API_KEY = "sk-local-qwen3"
& $PY "老师给的资料\MCEval_AgriQA代码\runners\run_experiment.py" `
    --model-config configs\models\qwen3_8b_llamacpp_local.yaml `
    --prompt-config "老师给的资料\MCEval_AgriQA代码\configs\prompts\zero_shot.yaml" `
    --input-file data\subsets\demo.jsonl `
    --fewshot-file "老师给的资料\MCEval_AgriQA代码\dataset\dev.jsonl" `
    --split test --seed 8888 --model-seed 8888 `
    --output-dir runs\demo_zero_shot --overwrite
```

`--limit N` 可以只跑前 N 题，`--skip-evaluation` 可以只生成不算分，`--overwrite` 清空重跑
（不加则**断点续跑**：已成功的题会跳过，失败的题会重试）。

## 4. 指标怎么算 —— 用刚才的真实结果讲透

这是本次 5 题冒烟测试的实测输出（`runs/demo_zero_shot/`）：

### 4.1 多选题：EM 和 Micro-F1

| | |
| --- | --- |
| 题目 | 引起植物产生药害的原因有() |
| 标准答案 | `ABCD` |
| 模型输出 | `answer:ABCD` |
| 结果 | ✅ EM = 100，Micro-F1 = 100 |

多选题是**集合比较**。如果模型只答了 `AB`，EM 就是 0（不及格），但 Micro-F1 会给出部分分
（`|AB ∩ ABCD| / |AB|` 和 `/|ABCD|` 都算一遍）。**EM 严格、Micro-F1 宽容**，两个一起看才知道
模型是"完全不会"还是"漏选"。

### 4.2 填空题：为什么需要 Token-F1

| | |
| --- | --- |
| 题目 | 用于描述政府对农业生产提供直接经济支持的政策是（） |
| 标准答案 | `农业补贴政策` |
| 模型输出 | `直接补贴政策` |
| 结果 | ❌ EM = 0，⚠️ **Token-F1 = 66.7** |

模型答的其实**意思基本对**，只是措辞不同。如果只看 EM（要求字符串完全相同），就判 0 分——
这正是论文要额外引入 Token-F1 的原因：`补贴政策` 4 个字重合 / 6 个字 = 66.7%。

> 这个例子完美体现了"EM 过严"的问题，也是这个基准设计的核心考量之一。

### 4.3 判断题：数据本身也可能有争议

| | |
| --- | --- |
| 题目 | 禾谷类作物一般都具有分蘖特性 |
| 标准答案 | `错误` |
| 模型输出 | `正确` |
| 结果 | ❌ Acc = 0 |

模型答错了，但**这道题本身值得商榷**：水稻、小麦、大麦都会分蘖，玉米一般不分蘖，
"一般都具有"到底算对还是错，存在解释空间。这类样本会造成**评测噪声**——
分析失败案例时要注意区分"模型真错"和"题目本身有歧义"。

### 4.4 开放题：必须用 LLM 当阅卷老师

简答题、术语解释、情景推理这三类**没有唯一标准答案**，字符串比对没意义，
所以论文用 **LLM Judge**：把「题目 + 标准答案 + 模型答案」一起交给 DeepSeek-Flash，
按农业评分细则（事实正确性、完整性、相关性、专业表达、推理质量、实用建议）打 1~5 分。

实测模型对情景推理题的回答（结构完整，含 reasoning + 原因分析 + 4 条管理建议）：

```
原因分析：重复喷施含同一种有效成分的两种药剂，导致该有效成分在植物体内积累，
         实际总剂量超过标签上限，引发药害，表现为花瓣和幼叶焦边。
管理建议：1. 避免重复使用含同一种有效成分的药剂，合理轮换使用不同作用机制的药剂；
         2. 严格按照标签推荐剂量施药...
```

> ⚠️ 本次跑分时 **LLM Score 是 null**，警告信息：
> `JUDGE_API_KEY/DEEPSEEK_API_KEY is not set; LLM Score is null.`
> 要拿到开放题的分数，需要配 DeepSeek API Key（见第 6 节）。

| 换 few-shot 抽取方式 | `prompts/fewshot_sampler.py` |
| 接新模型 | `configs/models/*.yaml` + `utils/model_loader.py` |
| 改答案后处理（抠答案） | `evaluation/postprocess_answers.py` |
| 改指标算法 | `evaluation/metrics.py`（主入口 `evaluate_predictions`） |
| 改阅卷细则 | `evaluation/llm_judge.py` |
| 任务分组规则 | `utils/task_mapping.py` |
| 跑单模型单策略全量 | `tools/run_full_prompt.py` |

**几个容易踩的坑（代码里写死的约束）**：

1. `tools/run_full_prompt.py` **只认**有序的 `agrieval_test_000001..000689`，且字段顺序必须严格等于九字段 schema，少一个都不行；
2. `--seed` 和 `--model-seed` **必须相同**，否则直接报错（防止静默混用）；
3. 689 题被拆成 **669 常规题（max_tokens=500）+ 20 推理题（max_tokens=1000）** 两批跑，不是一批；
4. 实验标准参数是 **seed=8888、temperature=0.15**，别随便改，否则和论文没法比。

## 6. 你的本地模型怎么接（已经配好了）

老师的框架原本只走 Ollama，但 `utils/model_loader.py` 里其实支持 **`openai_compatible`** provider，
只要服务暴露 OpenAI 格式接口就能直接接上 —— 你的 llama.cpp 正好就是。

**已创建的配置**：[configs/models/qwen3_8b_llamacpp_local.yaml](../configs/models/qwen3_8b_llamacpp_local.yaml)

```yaml
model_id: qwen3_8b_llamacpp_local
provider: openai_compatible          # ← 关键
model: qwen3-8b
base_url: http://127.0.0.1:8080/v1
api_key_env: LLAMACPP_API_KEY
temperature: 0.15
max_tokens: 500
seed: 8888
```

### ⚠️ 最大的坑：Qwen3 的思考模式

Qwen3 默认会先"想"再答。实测对比：

| 题目 | 开启思考（默认） | 关闭思考 |
| --- | --- | --- |
| 判断题 | 22.1s / 302 tokens → `正确` | **0.7s / 2 tokens** → `正确` |
| 单选题 | 36.8s / **500 tokens 耗尽，答案为空** ❌ | **0.9s / 4 tokens** → `answer: C` ✅ |
| 填空题 | 16.4s / 216 tokens → `氮肥；磷肥` | **1.0s / 6 tokens** → `氮肥；磷肥` |

思考过程会**吃光 500 token 的预算**，导致答案还没写出来就被截断。
老师原包里 `qwen3_8b_ollama_nothink.yaml` 就是干这个的。

**关闭方式**（PowerShell 里传 JSON 参数会被吃掉引号，必须用环境变量）：

```powershell
$env:LLAMA_ARG_CHAT_TEMPLATE_KWARGS = '{"enable_thinking": false}'
```

### 性能实测

- GPU：Intel Arc 140T 核显（Vulkan 后端 `ggml-vulkan.dll`）
- 速度：**约 13.6 tok/s**，关闭思考后单题典型 1 秒
- 显存/内存占用：约 9.5 GB
- 结论：**689 题全量评测在这台笔记本上可行**（按每题 2~10 秒估算，一轮全量约数小时）

### 开放题打分还需要一样东西

```powershell
$env:DEEPSEEK_API_KEY = "你的 key"
$env:JUDGE_BASE_URL   = "https://api.deepseek.com"
$env:JUDGE_MODEL      = "deepseek-flash"
```
